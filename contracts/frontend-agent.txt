The real commands are:
{"action":"instances.start","request":{...strict Request...},"kind":"example|counterexample","max_instances":16}
{"action":"instances.next","cursor":"opaque returned cursor"}
{"action":"instances.open","bundle_id":"returned bundle identity"}
{"action":"refinement.context","bundle_id":"base bundle","model_revision_sha256":"base revision","feedback":[...active labels...]}
{"action":"refinement.check","bundle_id":"base bundle","model_revision_sha256":"base revision","feedback":[...same labels...],"feedback_sha256":"returned digest","sql":"candidate SQL"}
Counterexamples require request.mode="analyze" plus a supported property, finite domain and bounds. Concrete compile/compare requests require the complete database; do not mix their fields with symbolic mode. Existing properties include only_value, no_value, max_rows and no_sql_error. Do not offer arbitrary policy text as executable policy. instances.start returns a record; follow instances.open to obtain its canonical bundle and validate the matching revision before showing the complete triple.

Enumeration response schema is sqlolla.enumeration_response.v1. Successful responses have status="ok", enumeration_status="instance|exhausted|limit", enumeration_exhausted, cursor, record, bundle_id, model_revision_sha256 and assurance_kind. The instance is record.instance, not a top-level field. Errors have status="error", code, message and enumeration_exhausted=false. Read session::open for its distinct bundle-and-records response shape rather than treating it as a next response.

Bundle schema is sqlolla.evidence_bundle.v1: request (including exact SQL and context), ir, model, output_schema, provenance, assumptions, kind, model_revision_sha256. Instance schema is sqlolla.instance.v1: instance_id, model_revision_sha256, kind, semantic_sha256, alloy_relations_sha256, assurance_kind, validation, semantic, alloy_relations, output_schema, facts and completeness. Facts carry stable JSON Pointer references. Use runtime shape validation and reject unsupported schema versions without rewriting evidence.

Preserve exact imported bytes and typed scalar identity. Some integer cells exceed JavaScript's safe-integer range: use lossless JSON parsing/serialization at the transport boundary and never coerce these values, decimal text, identifiers or cursors through Number. Preserve duplicate rows, JSON null versus SQL NULL, bytea and Unicode. Keep canonical evidence separate from formatted display values and AI context exports; do not claim a client-reconstructed hash authenticates the original bundle.
