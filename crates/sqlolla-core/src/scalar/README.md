# Scalar admission and maintenance

The value layer preserves PostgreSQL type identity, type modifiers, canonical transport spelling and a separate semantic comparison key. Existing `Cell` wire variants remain stable. Rich values use `{"type":"scalar","value":{"ty":...,"value":"PostgreSQL text spelling"}}`; deserialization reparses and validates the spelling instead of accepting a caller-supplied comparison key.

`Cell` collection equality preserves transport identity. SQL equality, duplicate equivalence and ordering use `compare_sql`/`duplicate_eq`. This distinction keeps numeric display scales, floating signed zero, enum identity, character modifiers and array dimensions observable. DISTINCT/group/set evaluation must preserve every permitted representative when a later cast can observe its display spelling.

Numeric uses exact integer coefficients and decimal scale with PostgreSQL16 division-scale selection, round-half-away-from-zero, typmod checks, infinities and NaN. Float8 uses PostgreSQL NaN/zero ordering and checked overflow/underflow. Date/time input currently admits ISO AD dates and numeric UTC offsets; calendar components remain distinct from interval comparison's thirty-day-month convention. No host clock, IANA timezone, locale service or PostgreSQL process is consulted by this crate. Unsupported input profiles and functions remain explicit `unsupported.*` failures, not successful SQL outcomes.

`abs` validates its single numeric overload before strict NULL handling; unknown string/NULL literals select float8, while typed nonnumeric arguments reject with SQLSTATE42883. Absolute value and numeric signs discard storage typmods without discarding display scale. The checked `FunctionResolution.lean` and `Values.lean` annotation contracts precede these fixes; actual PostgreSQL cases are maintained in `validation/collection_scalars.py`. Broader numeric/text builtin overload gaps remain explicitly listed in `capabilities.json`.

Character comparison distinguishes bpchar/varchar from explicit text coercion. `Name` stores at most 63 complete UTF-8 bytes. Arrays preserve rectangular dimensions, lower bounds and typed NULLs. JSONB retains last duplicate object keys, exact numeric semantics and storage-order key comparison. Bytea and fixed-width bits retain their binary meaning.

Primary references: [PostgreSQL16 numeric types](https://www.postgresql.org/docs/16/datatype-numeric.html), [numeric implementation](https://github.com/postgres/postgres/blob/REL_16_STABLE/src/backend/utils/adt/numeric.c), [JSON types](https://www.postgresql.org/docs/16/datatype-json.html), [array types](https://www.postgresql.org/docs/16/arrays.html). Dependencies are pinned `num-bigint 0.4.6` and `num-traits 0.2.19`; Cargo.lock records resolved checksums. The checked `contracts/m2/SQLollaM2/Values.lean` model provides partial abstract foundations, not a proof that this Rust implementation preserves all PostgreSQL semantics.

Before extending admission, add an explicit type/operator contract, execute independent PostgreSQL positive and adversarial fixtures, and then test the Rust implementation. Preserve SQLSTATE separately from unsupported/invalid/resource errors. Context-dependent clocks, catalog/session access, notification delivery, backend termination and declared SQL functions need explicit execution-context/effect contracts; they must never use corpus-result lookup shortcuts.

`Intervals.lean` was kernel-checked before the interval increment. `IntervalQualifier` keeps source ranges and fractional precision in expression metadata. An unknown literal uses its least specified field as the unmarked unit; an already typed text cast first parses ordinary seconds and then applies the qualifier. Truncation preserves larger fields, while precision0..6 rounds stored microseconds half away from zero. `make_interval` accepts the real seven argument slots with zero defaults and strict NULL behavior; its finite float8 seconds use nearest-even rounding before component addition. Canonical output uses PostgreSQL's `postgres` interval style and preserves independently signed months, days and microseconds.

The interval text profile accepts explicit unit quantities, SQL year-month/day-clock forms and at most18 fractional input digits. ISO designator syntax, precision-clamping warnings above6, nonfinite constructor seconds, and constructor integer/float conversion overflow remain explicit coverage refusals. These refusals do not claim that PostgreSQL rejects the input: PostgreSQL16 can wrap unchecked `make_interval` integer arithmetic. Interval-plus-interval currently refuses admission until its separate component-overflow contract is implemented. Text parsing and IEEE floating-point execution are checked by independent PostgreSQL fixtures; the Lean contract is not a proof of their implementation preservation.

Verbose fractional-unit input rounds exact half microseconds toward zero; clock fractions and `make_interval` use ties to even. Declared precision is a third path, rounding half away from zero. These rules are deliberately separate and tested at positive and negative ties.

Primary interval references: [PostgreSQL16 interval input](https://www.postgresql.org/docs/16/datatype-datetime.html#DATATYPE-INTERVAL-INPUT), [date/time functions](https://www.postgresql.org/docs/16/functions-datetime.html), and the pinned [timestamp implementation](https://github.com/postgres/postgres/blob/REL_16_16/src/backend/utils/adt/timestamp.c) and [input decoder](https://github.com/postgres/postgres/blob/REL_16_16/src/backend/utils/adt/datetime.c). Run `python validation/intervals.py` after rebuilding the shared CLI; its report separates semantic comparisons from intentional admission refusals.

`Oid`, `Regclass` and the internal catalog `"char"` preserve nominal identity. OID transport is unsigned 32-bit; the internal char is a single byte with octal escape transport. Regclass transport is numeric identity; symbolic rendering refuses admission without a separate catalog-rendering contract. `to_regclass` resolves against an explicitly complete relation inventory, effective search path and observed schema-USAGE map. No host database or connection is consulted. The Windows negative-OID input behavior outside the portable signed32 range remains a coverage refusal. Run `python validation/catalog_context.py` for actual PostgreSQL identity, quoting and permission comparisons.

Primitive text admission rejects NUL and values beyond 1 MiB, including unused parameters, database bags, session settings and literal defaults. These are invalid supplied inputs or resource refusals, distinct from modeled SQL failures. Scalar constructors and casts enforce the same byte limit on their results.

`Collections.lean` precedes JSON and collection execution. JSONB concatenation merges only the top level: object collisions choose the complete right value, arrays retain duplicates, and other operands become single array entries. Existence searches only top-level keys and string elements; any/all ignore NULL search-array elements. Array element access uses declared dimensions and lower bounds, returning SQL NULL for an absent dimension or index. Array slices clip each dimension, distinguish omitted bounds from SQL NULL, retain row-major order and reset output lower bounds to one. Append/prepend preserve nullable elements and nonempty lower bounds; dimension length is NULL for an absent dimension, while cardinality counts all elements. `get_bit(bit,int)` uses leftmost zero-based indexing and SQLSTATE 2202E outside the bit width; bytea bit access remains unimplemented.

Plain `Json` preserves source spelling, whitespace and duplicate keys. It has no SQL comparison operators. Its input profile currently accepts JSON representable by the pinned serde parser; unsupported Unicode-surrogate syntax is a coverage refusal rather than a fabricated PostgreSQL syntax error. JSON constructors retain NULL values and duplicate keys; JSONB constructors then normalize explicitly. Constructor date/time rendering follows the declared UTC/ISO profile. The runtime does not silently treat JSON text as JSONB. Run `python validation/collection_scalars.py` after rebuilding; the maintained report compares exact plain-JSON spelling and every decoded outcome against actual PostgreSQL. Its `--oracle-only` mode is explicitly not an implementation pass.

Collection references: [PostgreSQL16 JSON operators and constructors](https://www.postgresql.org/docs/16/functions-json.html), [array access](https://www.postgresql.org/docs/16/arrays.html#ARRAYS-ACCESSING), and [bit-string functions](https://www.postgresql.org/docs/16/functions-bitstring.html). These checked abstract contracts and differential cases do not establish a full compiler-preservation theorem.

`jsonb_set` updates existing parents only, creates a missing final slot when enabled, and preserves unrelated fields. Negative array path indexes count from the end; out-of-range final creation prepends or appends. NULL path components are errors only when traversal reaches them. Empty paths preserve the input, while scalar roots remain SQL errors. The scalar contract, parser admission, exact error boundaries and output-frame checks are exercised by the same collection harness.

`StringCollections.lean` defines the distinct NULL policies of `string_to_array`, `array_to_string`, and `jsonb_typeof`. A NULL split delimiter produces characters, an empty delimiter preserves a nonempty input as one field, and an empty input produces an empty array. Join skips NULL elements unless a replacement is supplied. SQL NULL remains distinct from JSON `null`. Builtin capability metadata refuses unimplemented bodies before any generic NULL shortcut; the shared function registry owns overload, volatility and effect classification.

`RegexSubset.lean` precedes the bounded regex matcher. It admits literals, Unicode literal characters, ASCII bracket ranges, anchors, grouping, alternation, and bounded/unbounded repetition. Case-insensitive matching is ASCII-only. The matcher retains all positional endpoints and reports exhaustion instead of returning false. Locale classes, lookaround, backreferences, embedded options, and non-ASCII insensitive matching remain explicit refusals. Pattern, input, syntax depth, and work limits are independent admission bounds. Run `python validation/regex_subset.py`; ordinary SQLSTATE errors and coverage refusals are reported separately. Reference: [PostgreSQL16 matching functions](https://www.postgresql.org/docs/16/functions-matching.html).

`SessionEffects.lean` supports the pure `evaluate_session_effect` API outside the scalar module. It consumes complete fixed advisory ownership and an immutable inherited event prefix, then returns a value and invocation-local delta. `Void` is a nominal result with an empty text spelling, distinct from SQL NULL and without SQL comparison operators. Notification events represent pending invocations; commit folds repeated channel/payload pairs in first-occurrence order, while rollback discards pending delivery. Known advisory conflicts refuse admission until scheduling/timeout semantics are supplied. The actual listener and `pg_locks` harness is `python validation/session_effects.py`; it distinguishes observed commit delivery from the internal pending trace, and neither API contacts a host database.

`XidScalars.lean` keeps transaction IDs nominal and unsigned32. SQL equality does not make xid an ordered or numeric SQL type. The xid-left/int4-right equality overload compares the integer's unchanged bit pattern; no reverse overload or explicit integer-to-xid cast is invented. The input parser shares PostgreSQL's base-zero uint32 profile with OID, including portable signed32 negative spellings. Wider negative spellings and overflow followed by an invalid suffix remain explicit coverage refusals because C `unsigned long` width changes accepted inputs or SQLSTATE precedence. Run `python validation/xid_scalars.py`; its platform-profile refusals are recorded separately from semantic comparisons. Primary implementation references: [xid functions](https://github.com/postgres/postgres/blob/REL_16_16/src/backend/utils/adt/xid.c) and [uint32 input](https://github.com/postgres/postgres/blob/REL_16_16/src/backend/utils/adt/numutils.c).

`BackendSignals.lean` precedes the pure backend signal handler. Its context declares complete stable process identities, role privileges and signal capability. A successful timeout-zero call emits `BackendTerminationRequested`; it does not imply immediate process exit or remove catalog rows. Missing PIDs return false with an observed SQL warning. Both requests and emitted warnings survive later SQL errors and rollback. Self-targeting, repeated requests to one PID, uncertain signal delivery, positive wait schedules and nonportable timeout widths remain refused. `python validation/backend_effects.py` uses only worker connections created in its disposable PostgreSQL cluster, observes eventual worker disappearance separately, and checks permissions, warnings and statement-error retention. The Rust core never sends an OS signal. Reference: [PostgreSQL16 backend signaling implementation](https://github.com/postgres/postgres/blob/REL_16_16/src/backend/storage/ipc/signalfuncs.c).
