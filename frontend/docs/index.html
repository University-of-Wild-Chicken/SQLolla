Quick Start

Start with a blank workbench. Describe a database model, edit its SQL, and see exactly which row breaks your rule.

Prefer to build a model by hand?

  1. Set up AI

    AI is optional: it drafts, explains and proposes fixes, while SQLolla’s local compiler and solver decide what is valid. Open the workbench and select AI settings. Choose OpenAI, Anthropic, or Gemini and enter that provider’s API key. Under Model, keep the recommended model (the one SQLolla is tested with) or select Check models for this key to pick another model your key can use. Then select Save in this tab · no send. You can also build and analyze a model by hand without a key.

  2. Describe the database and rule

    Choose Build with AI, then Build a database model from a description. Try this inventory check:

    Prompt 
    Model inventory(item_id int32, units int32) with at most one row and values 0, 1, and 5. Draft SELECT item_id, units FROM inventory and check that at most zero rows are returned.

    Select Share my description with my AI provider and click Generate database model. Review the proposed tables, modeled values, rule, and SQL. When it says Compiled locally, click Use this model and query to put the proposal in the editor.

  3. Edit and analyze the SQL

    Replace the SQL in the editor with the filtered query below. Choose Unintended behavior and click Analyze query.

    SQL 
    SELECT item_id, units
FROM inventory
WHERE units = 5

    For this rule, any returned row is a counterexample. The result shows an input and a returned row with units = 5. Open Table for the exact values or SQL / IR / Alloy for the underlying artifacts.

    Counterexample from the inventory demo
    Row item_id units
    Inventory input 5 5
    Query result 5 5

Build a model by hand

Use Schema and rule to specify the database and the inputs you want SQLolla to consider.

Tables
Enter a table name and declarations such as item_id:int32, units:int32. Use ? after a type for a nullable column, then choose Declare table.
Bounds and values
Set the maximum number of rows for each table. In Modeled values, add the finite values to consider for each column type.
Output rule
Choose the behavior to check, such as a maximum row count or a required value in a result column. Output column positions start at 1.

Type SQL directly or use Query builder to select columns, add filters, or join declared tables. In the builder, check the draft with the compiler and click Review as a new analysis to stage it.

The form covers int32, int64, text, and bool. Use Advanced request for additional supported types and context, including numbered parameters.

Read results

The result applies to the query, rule, row bounds, and values in the current request. Use Next counterexample or Next example to ask for another case.

Counterexample found
A concrete input causes the query to violate the rule within the model.
Example found
One modeled execution is available to inspect or preserve as a use case.
Exhausted within this exact model
The solver reports no further cases within the supplied context and bounds.
Configured limit reached
The search stopped at the case limit. Raise Maximum review cases to search for more.

Use Explain this case to ask a follow-up. With redaction enabled, the provider receives the verified rule outcome when available and can cite the evidence. The case SQL and cell values stay local. Your typed question goes through as written.

Review and refine

Label the visible case, then reopen or change your decisions in the bins at the bottom of the workbench.

Yes
Keep this behavior possible on the saved input.
No
Exclude this behavior on the saved input.
Unsure
Save the case for later review.

For a second generation from the same prompt, mark at least one case Yes or No. Use Regenerate SQL with AI or enter candidate SQL and select Check candidate SQL locally. The check replays the decided cases and tests the original bounded rule before you can stage a revision.

Troubleshooting

Why is Add table disabled?

The builder lists declared tables that are still available to add. Declare another table under Schema and rule, then select it in the builder.

Why does the compiler reject a table or column?

Check the names, types, and schema in the request. If the table is outside your search path, use its qualified name in SQL, such as public.inventory.

Why did I get no cases?

Check the analysis goal, the rule, and the row bounds. Add modeled values for the types your query uses, then run the analysis again. Exhaustion covers the exact finite model you supplied.

What if AI cannot return a usable draft?

Open AI settings to check your key and provider access. If you chose a model other than the recommended one, switch back: some models cannot return SQLolla’s structured output. If the local compiler rejects the proposal, read its diagnostic, then revise your description or edit the SQL directly.
